# UI調整前の画面一覧

`yamamoto/web-first-develop` の `a7e1123` から分岐した `codex/ui-screen-review` で、現在の画面を撮影します。アプリの画面・API・Prismaスキーマは変更しません。

## 起動と撮影

ローカルDBと開発サーバーをそれぞれ起動してから撮影します。

```powershell
npm.cmd run db:local
npm.cmd run dev
npm.cmd run ui:capture
npm.cmd run ui:gallery
npm.cmd run ui:verify
```

画面一覧は <http://127.0.0.1:4310/> です。検索、カテゴリへの移動、画像クリックによる拡大表示に対応します。画面の番号で修正箇所を指定できます。生成先は `.local/ui-review/2026-10-26/` です。`index.html` は直接ブラウザで開くこともできます。

`ui:capture` の後ろに工程名を渡すと、その工程を再撮影して既存一覧を更新します。例えば `npm.cmd run ui:capture -- "admin"`。工程名は `scripts/ui-review/capture.ts` の `stage` を参照してください。再撮影でも撮影専用ゲストを新しく作るため、獲得済みの状態に依存する工程は単独実行せず、全工程を実行してください。

## 撮影範囲

- 開始画面、登録前後のホーム、ガイド、QRカメラと許可エラー
- 全キャラの図鑑詳細3タブ、未獲得／獲得済み、獲得進捗
- プロフィール編集、保存完了、冒険の記録
- CPU対戦の選択、攻撃、防御、必殺、勝敗、再戦
- レイドの操作プレビュー、ルール、キャラ変更、WebGL代替表示
- 同期レイドの受付、選択、自動送信、待機、勝敗、回復、反撃、未入力、討伐成功、戦闘不能、再接続
- 展示リンクからの開始、獲得確認、成功、獲得済み、4学科コンプリート、無効リンク
- 管理者ログイン、一覧、絞り込み、検索、キャラ編集、3Dモデル、タグ発行、タグ無効化、4プロ解放条件
- 開発画面、404、3Dモデル確認ページ
- 会場スクリーンの通常、ローカル同期、演出デモ（1920×1080）
- 375×667／390×844／430×932のスマホサイズ比較

カメラは仮想映像、同期レイドの状態は実装済みの `LocalRaidRoom` を撮影用に再現します。OSのキーボードやブラウザUI、実障害を必要とする `error.tsx`、全APIのエラーメッセージは対象外です。

## データの扱い

撮影スクリプトはDB接続先とアプリURLがローカルであることを確認します。本番サーバーには接続しません。撮影専用ゲスト・管理者・タグだけを作成し、終了時に削除します。キャラ編集の保存リクエストをブロックし、撮影前後のキャラ・技・イベントの一致を確認します。DBの初期化、migration、seedは実行しません。

`manifest.json` に撮影条件・未完了工程・ブラウザ例外を、`verification.json` に画像サイズ・検索・拡大表示の確認結果を記録します。画像と生成HTMLはGit管理対象外の `.local/` に置きます。
