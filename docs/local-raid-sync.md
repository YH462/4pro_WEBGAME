# 実機スマホと会場スクリーンのローカル同期

## PCだけで演出を確認する

`http://localhost:3000/raid/screen?demo=effects` を開くと、スクリーン向けの3D演出デモを操作できます。同期スクリーン右下の「PC演出デモ」からも移動できます。

画面下で「通常攻撃」「2倍攻撃」「自己回復」「ボスの反撃」「ボス弱体」「討伐成功」を選択します。「連続デモ」で一巡再生でき、一時停止・再開・同じ演出の再生もできます。通常攻撃は緑のキャラの片手から青い光を放ち、2倍攻撃は両手から金色の二本の光を放ちます。発射時は手元が光り、軌跡がボスまで届くと衝撃波や装甲片が出ます。

「ボスのじゃんけん」では、ボスの前に浮かぶ光る紋章でグー・チョキ・パーを切り替えます。開始から2100msの「ぽん！」で最後の手を大きく表示し、光の輪ときらめきを広げます。ボス本体に腕や指を追加せず、どのモデルやイラストにも重ねられる画面上の演出です。初期値はパーで、「デモの手」のボタンから3種類をそれぞれ再生できます。連続デモは待機→じゃんけん→攻撃の順です。一時停止・タブ非表示中は演出と表示の時間が一緒に止まります。これは表示確認用で、スマホの勝敗や倍率には接続していません。

攻撃開始から650msで命中し、通常攻撃は90ms、2倍攻撃は140msだけ演出を停止します。停止解除時にボスののけぞりとHP減少が始まります。3D・光や粒子・画面上のエフェクト・HPバーは共通の時間軸で動き、一時停止中やタブを隠した間は進みません。

「ボスの反撃」は青い光を900msため、味方の列へ扇状に広がるブレスを放ちます。光の面・広がる波・星形の粒子が1550msで味方全員へ同時に命中し、それぞれの足元にしぶきと衝撃波が出ます。全員がのけぞって後退し、踏ん張って元の位置へ戻ります。反撃中はカメラを少し引いて全員の反応を見せます。反撃のダメージ処理はデモに追加せず、ボスHPは変わりません。

人数・HP・味方は演出確認用です。このモードは同期APIを呼び出さず、実際の戦闘状態や参加者データを変更しません。QRはスマホの操作プレビューにつながります。既存の3Dボスに装甲を追加した試作で、味方は簡易モデルです。WebGL非対応時は簡易イラストを表示し、動きを減らすOS設定にも対応します。

通常スクリーン `/raid/screen` にも同じ演出部品を組み込みました。`?sync=local` では操作した参加者本人のキャラから攻撃を発射し、自己回復も本人のキャラに表示します。緑のキャラへの固定はPCデモ用です。参加者ごとの表示位置・キャラ色と名前で見分けられます。味方の3Dモデルは仮表示です。[スクリーン仕様](raid-screen.md) に対応ルールと確認例を記載しています。

## 起動

PCとスマホを同じWi-Fiへ接続します。既存の `.env` では `APP_URL=http://localhost:3000`、`ALLOW_INSECURE_LOCAL_HTTP=true`、`ENABLE_DEV_SIMULATOR=true` を使います。

ターミナル1でDBを起動し、ターミナル2でLAN用の開発サーバーを起動します。

```powershell
npm.cmd run db:local
```

```powershell
npm.cmd run dev:lan
```

既に通常の `npm run dev` を動かしている場合は、先にそのサーバーを停止してください。IPアドレス入りのスマホ用URLは次で確認できます。

```powershell
npm.cmd run local:urls
```

- PCは `http://localhost:3000/raid/screen?sync=local` を開きます。
- スマホは、表示された `http://PCのLANアドレス:3000/battle/raid?sync=local` を開きます。スマホの `localhost` はPCを指しません。
- 初回はゲスト参加すると、そのまま同期用レイド画面へ戻ります。
- スクリーン右側の参加QRには、PCのLAN用URLが入ります。スマホの標準カメラで読み取り、表示されたリンクを開いてください。アプリ内のカメラはLAN上のHTTPでは利用できません。
- QRを押すと拡大表示できます。読み取れない場合は、QRの下に表示される参加URLをスマホへ入力してください。PCに複数のLANアドレスがある場合は、拡大画面の「接続先を選択」からスマホと同じネットワークを選べます。
- 参加者が入ったら、PCスクリーン下部の「10秒の入力受付を開始」を押します。全員共通の10秒カウントダウンが始まります。
- 受付中に攻撃／回復を選び、じゃんけんの手をタップするとそのまま送信されます。送信ボタンは不要です。次の受付では行動・手の選択がリセットされます。1人1ラウンド1回で、送信後の変更はできません。全員が送信済みでも10秒の締め切りまで待ちます。
- 締め切り後、全員共通のボスの手をスクリーンの「ぽん！」で公開し、それぞれの勝敗・倍率をスマホに表示します。全員の攻撃・回復、ボスの全体攻撃が続き、HPも命中に合わせて変化します。
- 結果は次の受付まで表示し、演出終了後に次の10秒の受付へ自動で移ります。「もう一度」ボタンは不要です。未入力の人は攻撃・回復を行いませんが、全体攻撃は受けます。演出中の新規参加者は次のラウンドから参加します。
- スクリーン右下「同期設定」→「同期をリセット」で再戦。接続中のスマホは自動で参加し直します。

ネットワークが変わるとLANアドレスも変わります。スマホから開けない場合は、同じWi-Fiか、PCが起動中か、Windowsのファイアウォールで開発サーバーへの接続が許可されているかを確認してください。LAN上のHTTPでは既存QRスキャナーのカメラは利用できないため、このテストはURLを直接開きます。

### Wi-Fi・テザリングを切り替えたとき

接続を切り替えた後は、開発サーバーのターミナルで `Ctrl+C` を押し、`npm.cmd run dev:lan` を実行し直してください。開発用の接続許可IPは起動時に読み込まれるため、URLだけ変えても操作できないことがあります。DBは起動したままで構いません。

続いて `npm.cmd run local:urls` で新しいスマホ用URLを確認し、そのURLをスマホで開き直します。PCスクリーンも再読み込みしてください。試作の戦闘状態はサーバー再起動で初期化されます。

参加QRのURLもスクリーンの再読み込み時に更新されます。PCにLANアドレスがない場合はQRを表示せず、Wi-Fi接続の案内を表示します。

ニックネーム入力後に同じ画面が再表示される、URLに `nickname=` が付く、または「画面を準備しています…」から進まない場合も、この再起動と開き直しを試してください。画面だけが表示され、操作用プログラムの読み込みが完了していない可能性があります。

## 同期する内容

- 参加人数、生存人数、各参加者が直近に選んだ行動。
- ボスHP・自分のHP・共有ラウンド・締め切り・送信済み人数・全員同時の攻撃／自己回復の演出。
- サーバーが選んだボスの手、勝敗、勝ち2倍・あいこ1倍・負け0.5倍、実際に適用した効果量。

`/api/local-raid` の共有状態を通常500msごとに取得します。参加者一覧には部屋内で安定した公開用IDを含め、直近10ラウンド（最大200人分）の結果に行動者・使用キャラ・共通のボスの手・効果量・前後のボスHPと本人HPを保存します。全員分をラウンドごとにまとめて再生します。再読み込みでは表示済みの段階を省き、未反映のじゃんけん・攻撃／回復・反撃から再開します。リセット時は古い演出を破棄します。参加者のID・キャラHPは既存のゲストセッションとDBから確認し、クライアントからHP・攻撃量・倍率は受け取りません。再送IDを保存し、同じ送信の再試行で行動を重複登録しません。古い部屋ID・ラウンドの送信、同じラウンドの二重送信は拒否します。

スクリーンは実際に「ぽん！」を表示したとき、部屋IDとラウンド番号を `reveal` で通知します。攻撃の停止解除・回復開始は `impact: action`、ボスの反撃命中は `impact: counter` で別々に通知します。スマホは `revealedTurn` で勝敗、`actionTurn` でボスHP・自己回復、`counterTurn` で自分のHP減少を公開します。回復直後に反撃される場合も、HPの増加→減少を分けて表示します。スマホのダメージ数値とのけぞりは反撃命中の通知で開始し、じゃんけん結果の表示中に先出ししません。参加者一覧のHPも同じ段階で更新します。

送信後から反撃が終わるまではスマホの取得を最大3秒保持し、状態の更新通知・リセットが来ればすぐ応答します。通信分の短い遅れは生じます。通知が失敗したスクリーンは再試行し、同じ通知が重なってもHPや演出を重複適用しません。サーバーは締め切り後に初めてボスの手と全員分の結果・HPを一括計算し、表示だけを演出に合わせて段階的に公開します。締め切り判定はサーバーの時計で行い、スマホの残り時間はサーバーから受け取った時刻との差を使います。キャラ変更は送信後から次の受付まで無効です。

スマホ上部はボスHP・共通ラウンド・参加人数だけを小さくまとめ、中央に選択した自分のキャラの正面向き3Dモデルを大きく表示します。名前・キャラ切替はモデルの上、自分のHPは直下です。敵のキャラクターモデルは表示しません。体験参加でも選択キャラの絵を表示し、体験状態は小さなバッジで示します。ボス・プレイヤー共通のHPゲージは一本の連続バーにくの字の境界線を重ね、数値を横に表示します。攻撃／回復は赤い切替ボタン、手は六角形ボタンで選択します。送信・待機・結果は同じ領域で切り替え、送信後と再読み込み後も受理された行動・手を確認できます。討伐後は送信操作を隠し、実際の個人結果を専用パネルに残します。前回の攻撃／回復は保持し、次の手は未選択へ戻るため、勝手な再送はありません。ルールとスクリーンへのリンクは「？」から確認できます。

待機中は次の送信・キャラ変更を無効にします。スマホを再読み込みしても送信済みの入力は保持され、参加キャラも復元します。スクリーンを開いていない・タブを非表示にして演出を止めている場合は結果と次の受付も待機するため、PCの同期スクリーンを前面に表示してください。スクリーンを開き直すと未反映の段階から再開し、演出終了の `finish` 通知で次の10秒を開始します。リセットすると待機を解除し、新しい部屋へ参加し直します。送信失敗時は同じ送信ID・行動で再送できます。

## 今回の簡易進行

10秒入力→全員共通のじゃんけん→全員同時の攻撃・回復→ボスの全体攻撃→次の10秒、の一斉ラウンド制です。最初の受付開始だけPCで操作し、以後は自動進行します。ラウンドは人数にかかわらず1回の演出にまとめます。

- ボスHP450、基本攻撃50、基本自己回復30は仮値です。
- ボスの手は締め切り後に1回だけ抽選し、各自の手と比較します。じゃんけん倍率を適用した後、回復は自分の最大HPが上限です。
- 攻撃の合計がボスの残りHPを超える場合、実際のダメージを各自の攻撃量に比例して整数配分します。送信の早さで有利にならず、合計も残りHPを超えません。
- 全員の攻撃・自己回復後にボスが生きていれば、そのラウンドに参加可能だった生存者全員へ20の反撃を与えます。未入力の人も対象ですが、演出中に初参加した人は次のラウンドから対象です（仮のテストルール）。
- キャラ変更・再読込でHPを全回復させず、キャラ変更はHP割合を維持します。
- ボスHP0は討伐成功。自分のHP0では行動不可。全員HP0では討伐失敗です。
- リセットは部屋IDとHP・履歴を初期化し、接続中の画面が新しい部屋へ参加し直します。閉じたスマホの参加情報は取り除かれます。

共有状態は開発サーバー1プロセスのメモリ上だけに保持し、サーバー再起動で消えます。所持キャラ・育成値・報酬は保存／変更しません。通常の `/battle/raid` は独立した操作プレビュー、`/raid/screen` は参加受付前のスクリーンです。演出の確認は引き続き `/raid/screen?demo=effects` を使用してください。

同期APIと同期画面は `config().simulator` が有効な開発環境だけで利用できます。LANからの更新は開発モード・明示的なローカルHTTP許可がある場合に限り、このPCのプライベートIPv4アドレスと同じポートのOriginを許可します。本番のOrigin検証・HTTPS要件は維持します。同期設定のリセットはローカルテスト用の操作で、正式なスタッフ認証ではありません。
