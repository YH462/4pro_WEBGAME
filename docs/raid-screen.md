# 会場レイドスクリーン UI

`/raid/screen` は会場投影用の16:9スクリーンです。演出確認で調整した3D・光・粒子・じゃんけんを共通の表示部品として使用します。ログイン・DB接続なしの初期状態は「参加受付前」で、参加者は0人です。

実際のスマホと同期する開発用モードは `/raid/screen?sync=local` と `/battle/raid?sync=local` です。LAN起動・実機URL・簡易戦闘ルールは [ローカル同期の手順](local-raid-sync.md) を参照してください。演出確認ページ `/raid/screen?demo=effects` は独立して残しており、仮データでの手動再生・連続再生・一時停止はそこで行います。

- 既存の赤白ハニカム背景、立体のキング・アクアとWebGL非対応時のイラストを再利用。
- 同期モードでは実際のボスHP・参加人数・生存人数と、参加者名・使用キャラ・各自のHPを表示。
- 縦横比を保って画面内に収め、16:9以外の表示領域には余白を設けます。
- 通常スクリーンは仮の戦闘を自動再生せず、同期モードではサーバーが確定した操作結果だけを再生します。
- 同期設定からリセットすると、古い部屋の再生中・再生待ちの演出を破棄し、新しい参加状況へ切り替えます。
- 右下の全画面ボタンで投影時に全画面表示へ切り替えます。

現在のスマホ連携は単一PCのメモリ上で動く開発用の一斉ラウンド制です。正式なイベント受付・管理者認証・報酬保存・公開サーバーへのデプロイは後続です。本番で開発用の同期APIを有効化する変更は行いません。

参加者が入ったらPCで「10秒の入力受付を開始」を押します。全員共通の締め切りと送信済み人数を表示し、各自が攻撃／回復とじゃんけんの手を1回だけ送信します。締め切り後、ボスの手を1回抽選し、全員同じ手と勝負します。じゃんけん→全員の攻撃・自己回復→全体反撃→必要なら討伐成功を再生し、生存者とボスが残れば次の10秒を自動で開始します。未入力では攻撃・回復をせず反撃だけ受け、演出中の初参加者は次のラウンドから参加します。

同期APIは部屋内で安定した公開用の参加者IDと直近10ラウンドの結果を返します。同じ種類のキャラを使用する人も別のID・表示位置で扱います。各ラウンドの全員分を1回の演出にまとめ、同じ結果の再取得・再送で演出を重複させません。再読み込みでは公開済みのじゃんけんを省き、攻撃／回復・反撃の未反映の段階から再開します。スクリーンが演出の完了を通知するまで次の受付を始めないため、人数分の待ち行列は作りません。

ボスHPの表示は全員の攻撃の命中と停止解除まで減らさず、ラウンドに保存した前後のHPを使います。スマホの勝敗・倍率・効果量は、共通のじゃんけんの「ぽん！」まで先出ししません。攻撃と回復が混在する場合も同じ時間軸で更新します。ボスが残れば全体ブレスを再生し、反撃開始から1550msで対象全員がのけぞり、スマホのHP減少・ダメージ数値も始まります。未入力者も反撃対象です。スクリーンの公開通知をサーバー経由でスマホへ届けるため、タブ非表示中もスマホだけ先に結果が出ません。結果・HPの同期には通信分の短い遅れが生じます。

## 決定した行動と倍率

スマホは「攻撃」「回復」の2択。攻撃対象はボス、回復対象は自分です。じゃんけんは勝ち2倍・あいこ1倍・負け0.5倍で、攻撃量と自己回復量の両方に適用します。共通ルールは `src/lib/raid-rps.ts` で管理します。旧資料の3ロール・防御・必殺コマンドは現在のレイドUIには表示しません。CPU対戦のルールは別です。

`/battle/raid` は同期画面と共通の、自分のキャラを主役にしたスマホUIです。攻撃／回復と手を選び「攻撃で試す」／「回復で試す」を押すと、約2.1秒の待機後にブラウザ内のランダムなボスの手と比較し、倍率と効果量の例を表示します。約2秒後に自動で選択へ戻ります。基本攻撃50・基本回復30は仮値。HP・所持データは変更せず、回復は他人に適用しません。同期モードでは従来どおりサーバーがボスの手と結果を確定し、スクリーンの公開通知まで待機します。

ローカル同期では10秒の受付と一斉戦闘を実装しています。正式なレイドでは管理者認証・イベントごとの設定・永続化を追加します。

PC演出デモ `/raid/screen?demo=effects` では、ボスの前にグー・チョキ・パーの光る紋章を浮かべ、「ぽん！」で最後の手を大きく公開します。じゃんけん専用の手や腕をボスの3Dモデルへ追加せず、関節構造にも依存しない画面上の演出とします。ボスを別のモデルやイラストへ差し替えても同じ演出を使用します。デモでは公開する手を選べます。同期連携時はサーバーが確定したボスの手を演出へ渡し、表示される手と勝敗計算に使った手を一致させます。表示アニメーションの途中で結果を再抽選しません。

## 決定した参加者とキャラの演出対応

ローカル同期では、スマホで操作した参加者本人のキャラから攻撃を発射し、自己回復も本人のキャラに表示します。3Dの味方は参加者ごとの色と名前で区別する仮モデルで、正式なキャラモデルは後続で差し替えます。

- 参加者IDとスクリーン上のキャラを対応づけます。同じ種類のキャラを使う参加者同士も、参加者IDで区別します。
- サーバーが確定した行動結果の参加者ID・使用キャラ・行動・倍率・効果量から、演出するキャラと内容を選びます。
- 通常攻撃は操作した本人のキャラの片手から青いビームを発射します。2倍攻撃は同じ本人のキャラの両手から金色のビームを2本発射します。ボスへの命中、のけぞり、HP減少は共通の時間軸にそろえます。
- 回復は操作した本人のキャラだけに回復エフェクトを表示し、本人のHPを回復します。
- 複数人の行動を同時に再生し、それぞれ本人のキャラを発射元・回復対象にします。勝ちの攻撃は金色2本、あいこは青1本、負けは薄い青1本で表現します。他の参加者の行動を、固定の代表キャラに集約しません。

確認例：Aさんが通常攻撃、Bさんが2倍攻撃、Cさんが回復を選んだ場合、Aさんのキャラから青いビーム、Bさんのキャラから金色のビーム2本、Cさんのキャラに回復エフェクトを表示します。

現在の `/raid/screen?demo=effects` はPCだけで演出を見るため、攻撃と自己回復を緑のキャラに固定しています。通常スクリーンと同期スクリーンには、デモ操作ボタンや架空の参加者を表示しません。
