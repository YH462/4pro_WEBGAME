## 旧設計案・確認用機能との区別

- `docs/architecture.md`、`docs/cpu-battle.md`、`docs/nfc-acquisition.md` 等に「レイド未実装」「追加7体が仮」などの古い記述が残る。実際は本番レイドは実装済み、仮フラグがあるキャラは1体。資料を現在の実装へ更新する必要がある。
- 以前の設計案には、受付締切時のキャラ固定、人数別ボスHP、10ターン／300秒制限、復活・バフ等がある。現在の本番レイドは別の簡略ルールで実装されており、旧案を全て実装する合意があるとは扱わない。採否の確認が必要。
- `/battle/raid?preview=1`、`/raid/screen?demo=effects`、`?sync=local` は意図した確認用機能。本番の通常URLは `/api/raid` とDBに接続しており、全体が仮データで動いているわけではない。
- モデル読み込み失敗時の代替表示や、所持前のシルエットは実装済みの表示処理であり、それ自体を未実装には数えない。
