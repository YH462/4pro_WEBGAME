# 同期レイドの攻撃・回復モーション

`3Dmodels/モーションファイル/` の原本から、骨・パーツ・マテリアルを含む独立したGLBを `public/models/motions/` に生成する。原本は保存し直さない。Blenderのオブジェクト名や骨が違うファイルへキーだけを流用せず、モーション用GLBのモデルを行動中だけ表示し、終了後はDBの通常モデルへ戻す。

## 対応素材

| キャラID | 素材 | 再生する行動 |
| --- | --- | --- |
| `thunder-fox` | E科ポケモン修正版 | 攻撃・回復 |
| `aqua-spirit` | C科 ポンタス | 攻撃・回復 |
| `temp-06` | Morinokami | 攻撃・回復 |
| `temp-08` | コートロン | 攻撃・回復 |
| `temp-09` | デンラコ | 攻撃・回復 |
| `temp-11` | ブシラッコ | 攻撃・回復 |
| ボス（DB外） | デスドラグーン・赤 | ボスの反撃 |

今回の攻撃・回復には、ボスの「対戦開始」「被攻撃」とブシラッコの行動区別なしGLBは使わない。ほかのキャラには従来のモデル・演出を維持する。

## 再出力

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --disable-autoexec --python-exit-code 1 --python scripts/export-raid-motions.py
node scripts/build-raid-motion-manifest.mjs
```

1体だけならBlenderコマンドに `-- --id=temp-09` 等を付ける。拡張子が `.blend 回復` 等になっている原本は `.local/` に `.blend` 名の作業コピーを作って読み込む。glTFの+Yが上・+Zが正面になるよう、出力GLB内の共通親に座標変換を保持する。デンラコは旧原本の上下を反転し、ブシラッコはモーション原本ですでに上下が直っているため二重反転しない。DBの通常モデルの正面角度は変更しない。

書き出し範囲は250フレーム等のシーン設定ではなく、実際のアクションのキー範囲から決定する。Morinokamiの高密度部分は骨を残して軽量化する。ボスはArmatureを残し、Mirror等を先に評価して左右の欠けを防ぐ。通常キャラの元モデルや図鑑画像は変更しない。

E科のアップロードGLBには、通常の `.blend` で非表示の制作素材（別置きのヘッドホン・リュック・平面等）も含まれている。`visibilitySource` の元Blender原本を読み、非表示オブジェクトをモーションの書き出しから除外する。原本にない新しい攻撃／回復エフェクトは残す。胴体の拡大縮小キー（攻撃で最大約1.57倍、回復で最小約0.8倍）は原本由来であり、キー自体は変更しない。

## 再生と同期

- 会場スクリーンは既存の共通演出時計の `visualMs` を使う。ヒットストップ・一時停止・タブ非表示による停止もその時計に従う。攻撃と回復が混在しても参加者IDごとに選んだモーションを同時再生する。
- スマホは本番サーバーが通知した `actionTurn` の増加に一度だけ反応する。送信ボタンを押した段階では再生しない。未送信者と、途中から開いた画面の過去の行動は再生しない。再読み込み・定期取得で繰り返さない。
- パーツごとに分かれたGLB内の複数クリップをまとめ、空白の開始時間を除いて再生する。元のキー間の時間比は維持し、通常キャラは2.2秒の行動枠に収める。ループせず、行動枠の後は通常モデルに戻す。
- 同じキャラの参加者も別のMixer・骨・表示状態を持つ。メッシュ／マテリアル／クリップのみ同じライブラリで共有する。モデル差し替え・離脱・画面終了ではMixerのバインドを解除する。
- スマホの表示範囲は通常モデル・攻撃・回復の全体を含めて一度決め、待機／再生／停止で画角を切り替えない。移動中の見切れと、開始・終了時に急に縮む／戻る見え方を防ぐ。モーション全体の範囲を共有テンプレートの読み込み時に計算し、毎フレームのCPUスキニング計算を避ける。動きを減らす設定ではモーションを再生しない。素材未読込・読込失敗では通常モデルと既存エフェクトを保つ。

HP・ダメージ・回復量・受付秒数・結果の保存処理は変更しない。モーションの終了や失敗が、サーバー側の行動結果を左右することはない。

## 既存DBとサーバー反映

モーション対応そのものはスキーマやDB内容を変更しない。`bundled-character-motions.json` に記録した通常GLBのSHA-256と正面角度がDBの登録モデルと一致する場合にだけ、`/api/character-models` へモーションURLを付ける。管理画面で独自モデルや角度へ変更した場合は自動で無効になり、別モデルへの誤適用を防ぐ。モデルIDごとのハッシュはサーバー内で最大128件キャッシュし、15秒ごとの取得でGLB本体を何度も読まない。

配布にはコード・マニフェスト・`public/models/motions/` を同じコミットから反映する。既存のデンラコ／ブシラッコは、先行する[通常モデルの向き修正](3d-models.md)もDBに反映済みである必要がある。モーションのためにキャラを作り直したり、NFC・所持データを変更したりする必要はない。

## 確認

`/models` の対応キャラに「攻撃」「回復」「停止」が出る。`/models?character=temp-09` などで1体だけ確認できる。静止した図鑑画像と通常GLBのダウンロードは従来どおり。レイド会場の演出デモではボスの反撃から攻撃モーションを確認できる。

`/raid/screen?demo=effects` の「確認するキャラ」で、DBに登録されたキャラを選ぶと、その1体を会場と同じ向き・演出で確認できる。読み込み後に「通常攻撃」「2倍攻撃」「自己回復」を押し、「今の演出をもう一度」で繰り返せる。`&character=temp-09` 等で確認対象を最初から指定できる。「4人デモ」は元の固定チームへ戻る。モーションのないキャラは標準演出になる。この選択は画面内だけの確認用データで、本番レイドへの参加・行動送信・DB変更は行わない。

単体テストは実GLBの構造・キー、複数クリップの結合、参加者間の独立性、通常モデルへの復帰とモデル照合を確認する。ブラウザーテストは6体の攻撃／回復・停止・モーションなしの表示と、同一キャラ2人が本番APIを通じて攻撃／回復を選び分ける同期ラウンドを検証する。

2026-10-28に本番用ビルドと型チェック、関連単体テスト21件、ブラウザー11件が成功した。複数WebGL画面の録画は受付中の描画を遅らせるため、同期モーションの検証では受付中の行動を本番APIで送信し、画面ごとの再生を確認する。操作ボタン経由のラウンド・再接続は別の既存ケースで確認した。スマホ実機での確認は別途行う。本番サーバー／本番DBには未反映。

同日のE科の追加調査では、元GLBと再出力GLBの本体各部を同時刻で比較し、動くパーツの座標と時間範囲が一致することを確認した。非表示素材の除外と画角固定を修正し、混入防止／画角の追加単体テストとE科の攻撃・回復・停止後の表示を確認する。
