# 場所ヒントの管理画面対応

ブランチ：`codex/collection-location-hints`。管理画面のキャラ編集に「場所のヒントを編集」を追加し、補足テキスト・写真・地図の登録、差し替え、削除、別タブでのプレビューを実装した。管理者セッションを必須とし、オリジン検証・入力検証・保存回数制限を既存の管理APIに合わせて適用する。

## 対象とレイアウト

- 4学科の `forest-golem`・`thunder-fox`・`flame-dragon`・`aqua-spirit`、ケイデンテラの `four-pro`、還暦だるまの `temp-12` は写真1枚と補足文。
- その他のIDは写真2枚を横並びにし、横長の地図と補足文を表示する。
- 固定IDを使うため、ローカルと本番で表示名・紹介文・並び順・学科設定が違っていても紐付けを維持する。保存APIはキャラ名・能力値・所持状態・獲得タグを更新しない。

## 画像とDB

静止画のJPEG・PNG・WebPを1枚8MiBまで受け付ける。Sharpで回転を補正し、写真は1600×1600px以内・WebP品質78、地図は2400×1600px以内・品質86に変換する。切り抜きや小さい画像の拡大をせず、EXIF等の付随情報を外す。保存済みの寸法・容量と合計容量を管理画面に表示する。

追加移行 `202611010001_character_location_hints` で `CharacterLocationHint` と `CharacterHintImage` を作成する。元画像は保存せず、最適化した画像と説明文をDBへ保存する。差し替えでは画像IDを新しくし、古い画像を削除する。トランザクションとヒント専用revisionで変更をまとめ、古い画面からの上書きを拒否する。既存キャラ編集のrevisionとは分離している。

## 検証

- Prismaスキーマ検証、クライアント生成、型チェック、本番ビルドに成功。
- 単体テスト237件に成功。画像の回転、寸法・縦横比、WebP化、EXIF除去、小さい画像の保持、不正形式・MIME不一致・容量超過・重複フォーム・キャラ設定変更の拒否を検証した。
- 専用DBの関連ブラウザテスト14シナリオで成功。画像登録と表示、再読み込み後の保存内容、プレビュー、150%への拡大、差し替え・削除と旧画像の404、同時編集の409、未ログイン・偽オリジンの拒否、6種類の写真1枚の設定、還暦だるまの写真登録、キャラ設定の維持を確認した。既存の図鑑閲覧・詳細表示・スワイプも確認した。
- 管理画面の390px・1366px、公開側のスマホ画面を撮影して確認した。

ローカルDBには過去の未適用移行3件もあったが、すべて新規テーブル作成のみであることと既存テーブルがないことを確認して適用した。seed・DBリセット・キャラ設定変更は行っていない。WindowsでDLLが使用中だったため、このプロジェクトの開発サーバーだけを停止してPrisma Clientを生成し、元と同じLAN設定で再起動した。

最後にローカルの `four-pro` が「4プロキャラ」、`temp-12` が「仮キャラ 12」のままであること、ヒントと画像は0件で検証用データが残っていないこと、localhost:3000のhealthが200であることを確認した。専用検証DBは終了し、開発サーバーは稼働を維持する。

## 公開サーバーへの反映方針

本番のキャラ設定が正しいため、コードとDB移行を反映した後、公開側の管理画面で素材を登録する方法を推奨する。ローカルDB全体は移さない。画像・文章の変更のたびの再デプロイは不要で、本番のDBバックアップにヒントと画像も含まれる。公開サーバーへの反映はまだ行っていない。
