# レイドのルール説明と途中参加

## 問題と修正計画

開始操作が直接10秒の入力受付へ進み、参加受付も開始と同時に閉じるため、操作を理解する前に戦闘が始まり、参加に間に合わない人がいた。

1. 開始操作と戦闘の間に30秒のルール説明を入れる。
2. 説明終了後のバトル開始から30秒間は、新しい人の参加を受け付ける。
3. 参加確定と待機の状態をスマホで明示し、既存の入力・演出・人数調整を維持する。

## 実装した動作

- 「ルール説明を開始（30秒）」で操作方法・倍率・残り秒数を表示し、終了後に自動で最初の入力受付を始める。
- スマホの実際の画面を使い、参加確定・攻撃／回復・じゃんけんの手・送信完了の4段階を8秒・8秒・8秒・6秒で説明する。画面内の対象を黄色の枠で強調し、同じ番号の説明文を表示する。参加QRは右側に残す。
- 待機中、説明中、バトル開始後30秒間は参加できる。開始ボタンから数えると60秒後に新規参加を締め切る。参加上限は20人。
- 入力受付中の参加はそのラウンドから、演出中の参加は次の入力受付から操作する。演出中に確定済みの結果や反撃は変更しない。人数による強さの更新も次の受付まで延期する。
- 参加前は「まだ参加は完了していません」、確定後は「参加完了！」、演出中の途中参加は「次の入力受付から操作できます」と案内する。
- QRと拡大QRは参加締め切りで消え、APIも新規参加を拒否する。既存参加者は再接続できる。部屋ID・解除済みの参加者・管理者権限の検証は維持する。
- 説明終了時刻と参加締め切りはサーバーで保存し、再読み込みで延長しない。旧版の進行中のバトルは従来の参加締め切りを維持し、次戦から新しい流れを適用する。DBスキーマ移行は不要。
