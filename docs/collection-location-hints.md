# 図鑑から場所のヒントを開く

一般の図鑑 `/collection` では、未獲得のキャラをタップすると `/collection/キャラID/hint` を開く。獲得済みは従来の詳細画面へ進み、獲得後にヒントURLを直接開いた場合も詳細へ移動する。ヒントの閲覧にゲスト登録は不要。

## 画面構成

| 対象 | 固定ID | 構成 |
| --- | --- | --- |
| 4学科のキャラ | `forest-golem`・`thunder-fox`・`flame-dragon`・`aqua-spirit` | 写真1枚と補足テキスト |
| ケイデンテラ | `four-pro` | 写真1枚と補足テキスト |
| 還暦だるま（12番の枠） | `temp-12` | 写真1枚と補足テキスト |
| その他 | 上記以外 | 遠くから・アップの写真2枚を横並び、その下に横長の地図と補足テキスト |

分類は固定IDで決める。表示名・紹介文・並び順・ローカルの学科設定を変更しても、ヒントの対象キャラは変わらない。画面の名前は各環境のキャラDBの現在の表示名を使う。ヒントの保存APIは名前・能力値・所持状態・獲得タグを変更しない。

写真と地図は切り抜かず全体を表示する。タップで拡大画面を開き、＋／－で100〜300%に拡大・縮小できる。拡大した画像はスクロールして確認する。閉じるボタン／Escapeで復帰する。未設定の内容は準備中を表示し、読み込みに失敗した画像だけ代替表示にする。

## 管理画面から登録する

1. 管理者としてログインし、キャラクター管理から対象キャラの「編集・タグ管理」を開く。
2. 「場所のヒントを編集」に場所名（200文字以内）と補足テキストを入力し、写真・必要な場合は地図を選ぶ。補足文は1000文字以内で、改行が使える。場所名はヒント画面のキャラ名の下に表示し、空欄なら「場所は準備中です」と案内する。
3. 必要に応じて「画像の説明」に目印を書く。画像を読み上げる際の説明にも使う。
4. 「場所のヒントを保存」を押す。保存済み画像の寸法・容量と合計容量が表示される。
5. 「保存済みのヒントを確認」で実際の配置を別タブで確認する。管理者の確認用画面は所持状態に関係なくヒントを表示する。

差し替えは新しい画像を選んで保存する。「○○を削除」も保存を押した時点で確定する。保存前は「画像の変更を取り消す」で元に戻せる。未変更の画像は維持される。別の管理画面で先に保存された場合は上書きせず、再読み込みを案内する。

## 画像の軽量化と保存

- 入力：静止画のJPEG・PNG・WebP、1枚8MiB、6400万画素まで。
- 写真：縦横比を保って1600×1600pxの範囲内へ縮小、WebP品質78。
- 地図：文字を読みやすくするため2400×1600pxの範囲内、WebP品質86。
- 小さい画像は拡大しない。撮影時の回転を補正し、EXIF等の付随情報を外す。ファイル容量は絵柄で変わるため、保存後の容量表示で確認する。
- 最適化した画像のみDBへ保存し、元の大きな画像は保存しない。差し替え・削除時に以前の画像データも削除する。
- 表示用画像URLは `/api/character-hint-images/画像ID`。差し替えるとIDが変わるため、古い画像のキャッシュを更新待ちにしない。

## ローカルと公開サーバーの扱い

本番のキャラ設定が正しい場合は、機能を反映した後に公開サーバーの管理画面から登録する方法を推奨する。ヒントの設定・画像はその環境のDBへ保存され、再起動・再ビルドでも維持される。登録のたびの再デプロイは不要。

ローカルで登録した内容は公開サーバーへ自動転送されない。ローカルの表示名が本番と違っていても、ローカルDB全体を本番へ移さずに動作確認できる。今回の実装ではローカルのキャラ名・能力値・所持データは変更していない。

導入には `202611010001_character_location_hints`（ヒント・画像の2テーブル）と `202611010002_character_hint_location`（場所名カラム）のDB移行が必要。既存キャラの値は書き換えず、保存済みのヒント・画像も保持する。公開サーバーでは通常のバックアップ後の更新・ビルド・web再作成で、既存Dockerfileの起動処理が `db:migrate` を実行する。初回反映後、管理画面で本番の名前とIDを確認してから素材を登録する。

Nginxのアップロード上限は既存のモデル登録と同じ25mを想定する。3枚の原本を送るので、413が出る場合は実際の公開サーバー側の上限を確認する。
