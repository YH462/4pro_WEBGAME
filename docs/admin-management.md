# 管理者画面

## 起動とログイン

`/admin/login` が管理者の入口です。参加者Cookieではログインできません。管理者アカウントは公開Web画面から作成せず、DBへ接続できる運営端末のコマンドで発行します。

```powershell
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run admin:user -- create operator
npm.cmd run dev:lan
```

WindowsでPrisma生成がDLLのロックにより失敗する場合は、開発サーバーを停止して生成し、その後起動します。DBと既存のプレイヤーデータは残します。

発行コマンドは、ユーザー名とランダム生成パスワードを `.local/admin/ユーザー名-日時-乱数.json` に保存し、そのファイルパスを表示します。パスワードはコンソールに表示しません。このフォルダはGit対象外です。運営だけがアクセスできる場所へ保管してください。共通の初期パスワードや認証を省略する開発用ログインはありません。

```powershell
npm.cmd run admin:user -- reset operator
npm.cmd run admin:user -- disable operator
```

`reset` は新しいパスワードを発行し、アカウントを有効にして既存セッションを破棄します。`disable` はアカウントと既存セッションを無効にします。

## キャラ一覧

- `/admin`：DBのキャラを一覧表示。名前・ID・学科名で検索し、学科キャラ／学科なし／条件解放で絞り込めます。
- カードには、設定イベント内の所持人数、有効タグ数、全タグ数を表示します。
- `/admin/characters/[id]`：そのキャラの情報編集、タグ発行と有効・無効の管理。
- 学科キャラ4体は学科に対応、4プロは4体を集めた条件解放、追加キャラは学科なしで扱います。追加キャラの獲得は4プロの解放数に含めません。
- 一覧の「編集・タグ管理」から既存キャラを編集できます。新規キャラの作成・削除はまだありません。

## キャラ情報を編集

名前（50文字以内）・紹介文（1000文字以内）・基本HP／攻撃／防御／チャージ効率を編集できます。HP・攻撃・防御は1〜10000の整数、チャージ効率は0〜10000の整数または空欄（未設定）です。旧「速さ」の値は変更しません。ID・所属学科・4プロの解放条件は固定です。

仮キャラを正式版へ差し替える場合は、名前や画像を更新して「仮キャラ（開発中）」のチェックを外します。`temp-06` などのIDを変更する必要はありません。既存タグURL・所持・獲得日時・育成の加算値を保持したまま反映します。基本値の変更は既に所持しているプレイヤーにも反映されます。学科キャラと4プロは仮キャラにできません。

キャラ画像は3Dモデルの正面から512pxの透過画像を自動作成します。画像を個別に選ぶ欄と属性の編集欄はありません。モデルや角度を変更すると画像も再作成し、「キャラ情報を保存」でGLB・画像・キャラ情報を同時に保存します。画像はサーバーでWebPへ変換してDBに保存し、ホーム・図鑑・獲得画面・CPU対戦にも使用します。画像生成にはWebGL対応ブラウザーが必要です。3Dモデルを外すと自動画像も削除して標準表示へ戻ります。属性の既存値は維持します。

保存した画像は管理者一覧・ホーム・図鑑・獲得画面・CPU対戦で使用します。未所持キャラのシルエット表示は維持します。スマホのレイドは配置済みのGLBモデルを優先し、GLB未設定のキャラはアップロード画像、画像も未設定なら仮3Dモデルを使います。WebGL非対応時は画像／イラストへ切り替えます。同じキャラ編集画面の「3Dモデル」からGLB（20MB以内）の登録・差し替え・削除・正面角度の調整ができます。モデル本体はDBに保存し、スマホのレイドと会場スクリーンへ反映します。[モデルの書き出しと配置](3d-models.md) を参照してください。

保存は画像と情報を同一トランザクションで処理します。複数の管理画面で同じキャラを開いた場合は、先に保存した内容を優先し、古い画面からの保存を409で拒否します。エラー時はページを再読み込みして最新の内容から編集してください。

## キャラ別タグ

接続先を選択して「このキャラのタグを発行」を押すと、対象キャラを固定したURLとQRが表示されます。同じキャラに複数のタグを作れます。4プロにはタグを発行できません。

**URLとQRは発行直後に保存してください。** 「URLをコピー」「QRを保存」「URLを保存」で手元に残します。管理画面を再読み込みすると原文は再表示しません。DBに保存するのはSHA-256だけです。発行レスポンスを受け取れなかった場合やURLを紛失した場合は、一覧で不要なタグを無効にし、新しいタグを発行します。

タグ一覧では有効・無効、発行日時（日本時間）、初回読み取り人数を確認できます。同じプレイヤーの同じタグへの繰り返しは人数に加算しません。所持人数とは別の数値です。既存所持者が読み取った場合も初回記録として残ります。

無効化してもキャラ所持は失われません。再有効化もできます。イベント終了後は発行・再有効化を拒否し、無効化だけを許可します。読み取り処理と無効化が重なった場合は先にロックした処理が先に確定します。

新しいタグは `AcquisitionTag.characterId` へ紐付けます。旧 `departmentId` 方式のタグは引き続き有効で、対応する学科キャラの管理画面から操作できます。既存のURLやQRを書き換える必要はありません。DB制約で対象はキャラ／学科の片方だけになります。

CLIも利用できます。

```powershell
npm.cmd run nfc:tags -- issue mechanical
npm.cmd run nfc:tags -- issue-character temp-06
```

接続先は `APP_URL` のオリジンと、明示的に有効な開発環境では現在のPCのLANアドレスに限定します。リクエストHostやクライアント入力を任意の発行先として信用しません。HTTPやlocalhostのURLはローカル確認用です。本番タグは固定のHTTPSホストで発行してください。

## 認証とAPI

- `AdminUser` にscrypt（個別salt、N=32768 / r=8 / p=3）でパスワードを保存。原文はDBに保存しません。
- `AdminSession` に256bit乱数tokenのhashと8時間の期限を保存。Cookieは `fourpro_admin`、HttpOnly、SameSite=Strict、Path=/、HTTPS環境でSecure。
- 管理画面の各ページと各APIでセッション・期限・アカウント有効状態を確認。画面の表示制御だけに依存しません。
- ログインはユーザー名ごと10回/分＋全体120回/分、タグ操作は管理者ごと30回/分。既存のOrigin・JSON・4KiB本文上限も使用します。
- `POST /api/admin/login` / `POST /api/admin/logout`。
- `GET /api/admin/tags?characterId=...`：設定イベント内のタグだけ。コード原文・hashは返しません。
- `POST /api/admin/tags`：キャラIDと許可済みオリジンから発行。コードはURLとして発行時のみ返します。
- `PATCH /api/admin/tags/[id]`：設定イベント内の有効状態だけ変更。対象キャラやイベントは変更できません。
- `PATCH /api/admin/characters/[id]`：認証とOriginを確認し、multipart入力の編集可能項目と画像だけを保存。管理者ごと20回/分。画像を含む本文は2MB＋16KiBに制限します。
- `GET /api/character-images/[id]`：検証・再変換済みの公開キャラ画像だけを返します。UUIDのURLを使い、画像変更時は新しいURLにしてキャッシュを更新します。
- 参加者のセッションは管理者ログイン・ログアウトと独立し、管理者ログアウトでも参加者の進行状況は保持します。

## 検証

```powershell
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:e2e -- tests/e2e/admin.spec.ts tests/e2e/acquisition.spec.ts --project=chromium
npm.cmd run test:e2e -- tests/e2e/character-edit.spec.ts --project=chromium
```

管理者とゲストの分離、ログアウト・期限切れ・アカウント無効化、CLI発行とパスワードリセット、追加キャラの獲得、4プロのタグ拒否、別イベント／不正Originの拒否、既存学科タグと4学科解放の維持を実DBで確認します。

編集では仮キャラの正式化、画像保存・再表示・削除、NFCと所持・育成値の保持、図鑑・スマホへの反映、不正画像・不正入力・同時保存の拒否を実DBで確認します。テスト用に作成したキャラだけを編集・削除します。
