# 管理者用リアルタイム統計・ランキング・CSV出力 計画

作成日：2026-10-30。現行main `4ab2644` と既存のDB構造を確認した設計案。
2026-10-30に統計ページ・管理者API・CSV／ZIP出力を実装し、専用検証DBで確認済み。参加者初期化は別作業であり、この機能には含めない。本番反映は別途必要。

## 1. 決定済みの要件

- 管理者だけが閲覧できる1ページの統計画面を作る。予定URLは `/admin/statistics`。
- ランキングは「収集数」「討伐成功数」「討伐ポイント」の3タブ。参加者のニックネームを表示する。
- 既存の参加者・所持キャラ・完了したレイド・報酬台帳から集計し、CSVへ出力する。
- 画面は5秒間隔で自動更新する。戦闘スクリーンとは別ページで、ゲーム進行を操作しない。
- 本番の参加者データを削除する前に、デモの記録を持ち出せるようにする。

## 2. 初版の対象と区切り

初版は、アプリに設定された `EVENT_ID` の現存データ全期間を対象とする。
別イベントのデータを任意のID指定で取得するAPIは作らない。
新しいDBテーブルや既存データの書き換えは不要とする。

デモ終了時にCSV一式と復元用DBバックアップを保存し、別途用意する参加者初期化の手順を実行する。
初期化後の本番データを新しい集計として扱う。`EVENT_ID` や展示QRの発行情報を変更して区切る方法は採らない。
初期化されていないデモと本番を自動判別する機能は初版に含めない。

初期化したデモの履歴はダッシュボードでは表示できなくなる。保存したCSVで参照・分析する。
CSVは集計・分析用であり、アカウントやセッションを復元するDBバックアップの代わりにはしない。
統計ページに参加者削除ボタンは置かず、初期化は別の作業として扱う。

## 3. 画面と集計指標

### 上段：6つの指標カード

| 指標 | 定義 |
| --- | --- |
| 参加登録数 | 対象イベントの `Player` 件数。実際の来場人数・オンライン人数とは区別する |
| 収集参加者数 | 1体以上の `PlayerCharacter` を持つ参加者の人数 |
| 4学科達成人数／率 | 指定の4学科すべてを所持する参加者数。率の分母は参加登録数 |
| レイド参加者数 | 完了したレイドの `RaidResult` を1件以上持つ参加者の人数。途中参加・未完了は含めない |
| 完了した戦闘数 | `RaidResult` の異なる `roomId` 数 |
| 討伐成功率 | 討伐成功した戦闘数 ÷ 完了した戦闘数。参加者ごとの記録を重複計上しない |

分母が0の割合は「—」、人数・件数の0は「0」とする。未取得は0件と区別して読み込み表示にする。

### 中段：グラフと戦闘状況

- 日別・時間帯別の参加登録数：`Player.createdAt` を日本時間の1時間単位で集計する。
- キャラ別獲得人数：`PlayerCharacter` をキャラ別に数える。体験使用は含めない。
  自動解放の4プロは「コンプリート報酬」と明示し、展示での獲得と区別する。
- 学科別獲得人数：4学科を個別に比較する。4学科達成の割合も表示する。
- レイドの成功／全滅、成功戦闘の平均ターン数、終了戦闘の参加者数ごとの成績を表示する。
  各戦闘の参加者数は、その試合の完了記録に残る参加者数として扱う。
- キャラ別レイド使用数は、完了した戦闘の参加記録を数える。
- 現在の待機・戦闘状況を表示する場合は、保存済み `RaidRoom` を読み取りのみで参照する。
  「参加登録中の人数」とし、ページを閉じた端末を含み得ることを定義上区別する。

実際の来場人数、現在のオンライン人数、正確な滞在時間、戦闘所要時間、全QR読取回数は初版の指標にしない。
現在の `AcquisitionLog` は参加者とタグの組み合わせが一意なので、繰り返し読取の総回数は復元できない。
獲得順は `PlayerCharacter.acquiredAt` から推測できるが、物理的な移動経路の実測として表示しない。

### 下段：ランキング

| タブ | 順位の基準 |
| --- | --- |
| 収集数 | 参加者の異なる所持キャラ数。4プロを含み、プロフィールの獲得数と一致させる |
| 討伐成功数 | 参加者の `RaidResult` のうち `won=true` の件数 |
| 討伐ポイント | 参加者の `RaidReward.points` の合計。勝利数から推測せず実際の台帳を使う |

- ニックネーム、順位、収集数、討伐成功数、ポイントを表示する。タブで順位の基準を切り替える。
- 初期表示は上位10人とし、全件も閲覧できるようにする。
- 同じ値は同順位とする（1位・1位・3位）。同順位内の並びは登録日時・参加者IDで安定させる。
- 選択した指標が0の人はそのランキングに表示しない。参加者CSVには0の人も含める。
- 名前未入力は「ゲスト」。同名・ゲストの区別には参加者IDから作る表示用識別子を添える。
  集計とCSV上の同一人物判定には完全な参加者IDを使い、ニックネームでは結合しない。
- 現状は成功1回100ポイントなので、討伐成功数とポイントの順位は基本的に同じになる。
  ポイント制度が変わっても、それぞれ元の記録から集計する。

## 4. 見た目と操作

- 既存の4PROに合わせ、白を基調に赤・濃紺・金をアクセントにしたダッシュボードにする。
  六角形の装飾は見出しや順位表示に絞り、数値とグラフを読みやすくする。
- 上位3人は金・銀・銅で強調。大きな数値カードと横棒グラフを中心にする。
- 説明・ラベルは原則14px以上、本文16px前後。小さい灰色文字に情報を詰め込まない。
- PCでは複数列、狭い画面では縦積み。横にはみ出す表は表の領域だけスクロールする。
- ヘッダーにイベント名、最終更新時刻、更新状態、「今すぐ更新」「CSV出力」「全画面」を配置する。
- 非表示タブでは取得を止め、戻った際に更新する。取得の重複と古い応答による上書きを防ぐ。
- 通信失敗では最後の正常な統計を維持し、取得失敗と最終成功時刻を表示する。
- 表示アニメーションを控えめにし、動きを減らすOS設定にも対応する。

## 5. CSVの構成

画面の「CSV出力」から全5ファイルをZIPでまとめて保存でき、個別のCSV出力にも対応する。
ZIPの全ファイルは、同じDB読み取りスナップショット・出力時刻で生成する。
初版では期間・日付フィルターを付けず、現イベント全期間のデータを出力する。

| ファイル | 1行の単位／主な列 |
| --- | --- |
| `summary.csv` | 指標1件／指標名・値・単位・イベントID・出力時刻 |
| `participants.csv` | 参加者1人／参加者ID・ニックネーム・登録日時・収集数・学科数・完了レイド数・討伐成功数・ポイント・各ランキング順位 |
| `collections.csv` | 参加者と獲得キャラ1組／参加者ID・ニックネーム・キャラID・現在の名前・学科・レジェンド区分・獲得日時 |
| `raids.csv` | 完了した戦闘1件／roomId・ボス名・勝敗・ターン数・記録された参加者数・完了日時 |
| `raid-participants.csv` | 戦闘と参加者1組／roomId・参加者ID・ニックネーム・使用キャラID・戦闘時のキャラ名・勝敗・ターン数・完了日時・実際の付与ポイント |

- UTF-8 BOM付き、CRLF改行、CSV標準の引用符・改行・カンマ処理に対応し、Excelでも読める形式にする。
- 日時は日本時間・時差付き形式で統一する。ファイル名にもイベントIDと出力日時を付ける。
- ニックネームを含む文字列セルは数式実行を防ぐ処理を行う。DBの元の名前は変更しない。
- パスワード・セッショントークン・タグの認証情報・モデル本体は出力しない。
- CSVの計算式を画面と別に持たず、共通の集計処理を使う。出力ファイルに全件を含める。

## 6. 実装構成

- `/admin/statistics`：管理者認証を通した統計ページ。管理画面ヘッダーからリンクする。
- `/api/admin/statistics`：5秒更新用のJSON。認証済み管理者のみ、`private, no-store`。
- `/api/admin/statistics/export`：形式・対象ファイルを許可リストで指定し、CSV／ZIPを取得する。
- `src/lib/event-statistics.ts`（予定）：イベント範囲の集計・ランキング・指標定義を共通化する。
- `src/lib/statistics-csv.ts`（予定）：CSVの整形・数式対策・出力ファイルの組み立てを担当する。
- ページ、JSON、CSV、ZIPのすべてで管理者認証を確認する。
  統計への直接アクセス後、ログインして元のページへ戻れるようログイン先の許可リストを拡張する。
- DBからは必要な列だけを取得し、まとまったクエリで集計する。参加者ごとに個別問い合わせを繰り返さない。
- 統計の読み取りで報酬付与・戦闘進行・タグ発行・参加者変更は実行しない。
  終了済みイベントの記録も、削除前までは閲覧・出力可能にする。

## 7. 実装順と完了条件

1. 指標の共通集計処理とランキングを作り、0件・同順位・同名・イベント境界・戦闘の重複計上を検証する。
2. 管理者限定JSON APIと5種CSV／ZIPを実装する。日本語・カンマ・改行・数式形式のニックネームを検証する。
3. 1ページのダッシュボードと自動更新、管理画面への導線を作る。
4. 専用ローカルDBで実際の獲得・4学科達成・勝利・全滅からの反映を確認する。
   20人の1戦を「20戦」と誤計上しないこと、体験キャラを収集数へ入れないことを確認する。
5. スマホ・PC表示、取得失敗時の保持、ログアウト・セッション期限切れ時の保護、CSVと画面の数値一致を確認する。
6. ローカルで見た目を確認後、コミット・プッシュ・main統合・本番反映を行う。
   本番でCSVを保存・開いて確認してから、別途デモ参加者初期化の作業へ進む。

当日の実人数計測、追加の行動ログ、過去CSVを再アップロードして表示するアーカイブ画面、公開ランキングは初版の対象外とする。
