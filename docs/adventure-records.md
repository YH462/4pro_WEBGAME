# 冒険の記録

プロフィールの「冒険の記録」には、本人の収集したパートナー・討伐成功数・完了したレイド数と最近20件の勝敗を表示する。所持キャラは同期レイドの参加判定と同じ `PlayerCharacter` を参照し、レイド結果は `RaidResult` に保存する。

## 収集と表示更新

- NFC／展示QRで獲得したキャラと、4学科コンプリート時の4プロを一覧・獲得数へ反映する。名前・画像は現在のキャラマスタを使用する。
- 重複読み取りで獲得数は増えない。レイドで未所持キャラを体験使用しても所持へ追加しない。
- 記録タブを開いた時、前面へ戻った時、および表示中3秒ごとに `/api/profile/records` から更新する。プロフィール編集タブや非表示の画面では定期取得しない。
- 通信失敗時は最後に取得できた記録を維持してエラーを表示する。次の更新に成功するとエラーを消す。
- APIはゲストCookieから本人を特定し、任意のプレイヤーIDを受け付けない。未認証・別イベントのセッションは401。応答は `private, no-store`。

## レイド結果の保存

- 本番 `/api/raid` で戦闘の完了を確定する時、部屋の状態更新と同じDBトランザクションで参加者ごとの結果を保存する。
- ボスHPが0なら討伐成功、生存者がいなくなった場合は全滅として記録する。ラウンドの対象になった参加者が記録対象で、最終ラウンドの演出中に初参加しただけの人は対象外。
- `roomId + playerId` の一意制約と部屋の保存済みフラグで、再送・再接続・複数プロセスからの重複を防ぐ。名前・使用キャラ・ラウンド数・結果時刻をスナップショットとして保持する。
- 討伐後の新規参加は拒否する。既存参加者は終了時の状態を再取得できるが、参加キャラを変更しない。
- 途中リセットを勝敗として数えない。完了後のリセットでは部屋だけを初期化し、個人の戦績を残す。未記録の終了済み部屋が残っている場合は、リセット前に記録を保存する。
- この機能の追加前にリセット済みの戦績は元データがないため復元しない。完了した討伐に対するポイント・称号・バッジは [報酬](player-awards.md) を参照。成長値の付与は未実装。
- イベント終了後も記録を閲覧できる。保存期限後の既存purgeでプレイヤーを削除すると、その人のレイド記録も外部キーのcascadeで削除する。

## DB移行

`202610270001_adventure_records` は `RaidResult` テーブル・索引・外部キーの追加のみ。既存の所持・NFCタグ・キャラマスタを変更しない。公開前に対象環境で通常の `npm run db:migrate` を実行する。今回の作業では専用ローカルDBにのみ適用し、本番DBには適用していない。
