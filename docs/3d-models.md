# Blenderモデルの書き出しと配置

元データはプロジェクト直下の `3Dmodels/`、ブラウザーで使う書き出し先は `public/models/characters/` です。元の `.blend` は保存し直さず、GLBだけを更新します。

## ファイルとキャラの対応

| 学科 | Blenderファイル | GLB | 既存キャラID |
| --- | --- | --- | --- |
| M：機械科 | `M科ポケモン.blend` | `m.glb` | `forest-golem` |
| E：電気情報 | `E科ポケモン修正版.blend` | `e.glb` | `thunder-fox` |
| S：電子制御 | `S科ポケモン_リセンコ.blend` | `s.glb` | `flame-dragon` |
| C：建設システム | `C科ポケモン_ポンタス.blend` | `c.glb` | `aqua-spirit` |

対応は属性ではなくキャラIDで固定します。名前・属性・能力値・所持データは変更していません。キャラ名は管理画面から変更できます。

## 更新するとき

1. Blenderで元ファイルを編集して保存します。
2. プロジェクトのフォルダーで、PowerShellから次を実行します。Blenderのインストール先が異なる場合は実行ファイルのパスを変更してください。

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --factory-startup --disable-autoexec --python-exit-code 1 --python scripts/export-character-models.py
```

3. `npm run dev` でゲームを起動し、`http://127.0.0.1:3000/models` を開きます。4体のモデルをログインなしで確認・ダウンロードできます。
4. スマホの `/battle/raid`、会場用の `/raid/screen?demo=effects` でも確認します。ファイル更新後にページを再読み込みしてください。

書き出しスクリプトは各学科の `.blend` が1つずつあることを確認し、現在表示されているメッシュ・リグ・Emptyを選択してGLBへ出力します。カメラ・ライト・非表示の作業用パーツは除外し、ミラーなどのモディファイアを反映します。マテリアルと使用テクスチャをGLBへ含め、圧縮専用デコーダーは使いません。今回の4ファイルをBlender 5.2で書き出して確認しています。

手動の場合は、オブジェクトモードで必要なパーツを選択し、「ファイル → エクスポート → glTF 2.0」を開きます。形式を「glTF Binary (.glb)」、対象を「選択したオブジェクト」にし、マテリアル・UV・モディファイアの設定を確認して、上記のGLBを更新してください。一般的な画像テクスチャとPrincipled BSDFを使うと移植しやすくなります。

## ゲームでの表示

- `src/lib/character-models.ts` がファイルの対応と正面補正を管理します。元データの正面はM/SがBlenderの+X、Eが+Y、Cが-Yです。ゲーム側で正面を+Zにそろえ、足元をY=0、高さを2に統一します。元データの向きを変えた場合は、この補正も確認してください。
- スマホは正面固定でGLBを表示します。GLBがある4体は管理画面の2D画像より3D表示を優先します。読み込み中はローディングを表示し、正式モデルの最初のフレームが描画できてから表示します。失敗時は仮3Dモデル、WebGL非対応・コンテキスト喪失時は2D画像／イラストへ切り替えます。
- 会場スクリーンは参加者のキャラIDに対応したモデルを表示します。同じキャラの参加者同士はモデルのリソースを共有します。攻撃の発射位置は共通の仮想アンカーを使用し、リグの有無に依存しません。反動・上下移動・勝利時の動きは既存の演出を維持しています。
- GLB内のアニメーションクリップは自動再生しません。ボーンを使った待機・攻撃などのモーション切替は別途実装が必要です。
- ホーム・図鑑・獲得・CPU対戦のキャラ絵は既存の2D表示です。4プロ・追加の仮キャラ・ボスには今回の4モデルを割り当てていません。
- 管理画面からのGLBアップロードには対応していません。モデルを変更するときはファイルを書き出し、サイト更新時にGLBも一緒に配置します。
